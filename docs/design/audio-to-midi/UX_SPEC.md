# MR Studio — Audio-to-MIDI UX / Техническое задание

> **Версия документа:** 0.1 · **Дата:** 11.11.2026 · **Статус:** визуальное и поведенческое ТЗ для реализации после согласования.  
> **Источник:** `MR_Studio_Audio_to_MIDI_UX_TZ_v0.1.docx` (созданный в рабочем чате оригинал с 7 PNG-макетами).  
> **Важное:** ТЗ описывает ожидаемый UX, **не является доказательством реализованных функций**, не меняет состояние GitHub Issues и не разрешает merge в `main`.

## 0. Карта двух сценариев

![Два сценария](mockups/07_two_workflows.png)

| Отдельный готовый аудиостем | Полный микс |
|---|---|
| Выбрать клип или произвольный фрагмент → **Drag & Drop на существующую Instrument Track** | ПКМ по аудиоклипу / выделению → **Convert to MIDI** |
| Выбрать **модель и один инструмент** | Выбрать **модель** |
| Общее окно прогресса | То же окно прогресса |
| Автоматически создаётся **один MIDI-клип на целевой дорожке** | Выбор партий галочками → создаются новые MIDI-дорожки |

### Зафиксированные границы
- Одна и та же компактная панель процесса для обоих сценариев: progress bar, корректный процент или indeterminate, chunks `n/N`, elapsed timer и название текущей операции рядом с таймером.
- Выбор CPU Threads, Compute Device, quantization, grid/strength, default velocity и управление моделями — **только в `Preferences → Audio-to-MIDI`**, без технических параметров в стартовом диалоге.
- Основной runtime — **Python/PyTorch**. На текущем этапе в списке фактически доступна **только MuScriptor Medium**. C++ HOT-Step / экспериментальный A/B, Small и Large в новом UX не показываются.
- Аудиоисточник не изменять. ML-вызовы и файловые операции не выполнять в JUCE/ASIO realtime callback. Пользовательская приёмка отдельно.

## 1. Графический стиль
Сохранить принятую тёмную графитовую/сине-графитовую тему MR Studio: тонкие контуры, холодный серо-синий акцент, компактный ритм отступов, чёткие подписи, минимальное число кнопок. Макеты **эталон композиции, структуры и текста**, но реальные токены цветов, шрифты и DPI определяются действующим MR Unified Design System и UI-компонентами репозитория. Не перепроектировать DAW в рамках этого UX.

## 2. Сценарий A: готовый стем → инструментальная дорожка

![Drag & Drop аудио на Instrument Track](mockups/01_timeline_drag_drop.png)

1. Пользователь выделяет целый аудиоклип или диапазон внутри аудиоклипа **без обязательной нарезки** файла.
2. При drag на совместимую `Instrument Track` показывать **контурное превью целевого размещения**; аудиоклип на этой дорожке не создаётся.
3. На drop зафиксировать `sourceClipId`, `sourceRevision`, выбранные sample-границы и позиции диапазона, `targetTrackId`, точную позицию на таймлайне с учётом snap.
4. Показать небольшое окно **рядом с курсором** с проверкой границ дисплея. Только модель + ровно **одна** инструментальная категория. Тип стема из MR Separation можно использовать для предвыбора категории, если данные достоверны; выбор всегда можно изменить.
5. Кнопка **«Конвертировать»** запускает Python worker. После успешного завершения проверить существование и revision целевой дорожки; **автоматически** создать на ней **один редактируемый MIDI-клип**, без второго мастера/подтверждения/списка партий.
6. MIDI-клип помещается на позицию drop; времена нот внутри обрабатываемого фрагмента пересчитываются по текущей tempo map. Исходное WAV и ранее существовавшие клипы не изменяются.

![Окно для готового стема](mockups/02_stem_convert_dialog.png)

**Поля:** отображаемый источник; `Модель распознавания: MuScriptor Medium`; `Инструмент партии: Electric Bass` (пример, только одна категория); кнопки `Отмена` и `Конвертировать`. **Никаких CPU/GPU, quantize, длительных опций, дополнительных MIDI-партий.**

**Семантика:** instrument означает штатное ограничение распознавания/декодирования моделью (`--instruments` / API) **до одной категории**, а не выбор VSTi и не постфактум переименование GM программы. Выделенный стем — входное аудио, а не команда разделить микс на стемы.

## 3. Общее окно обработки — для обоих сценариев

![Единое окно прогресса](mockups/03_shared_progress.png)

| Элемент | Требование |
|---|---|
| Заголовок | `Audio-to-MIDI — Обработка`; модель + контекст `Bass Stem → MIDI` или `Full Mix → MIDI` |
| Progress Bar | Достоверные 0–100 % только при наличии оценки от worker; иначе неопределённый прогресс. **Chunks сами по себе не равны общему проценту**: есть загрузка модели и постобработка |
| Chunks | `n / N` фактически обработанных сегментов; для MuScriptor обычно 5 секунд/segment, только по реальной информации модели |
| Elapsed | Реальный монотонный таймер с запуска job, включая подготовку/загрузку; формат `MM:SS` или `HH:MM:SS` |
| Операция | Текст **рядом с таймером/в той же компактной зоне**: `Загрузка модели`, `Подготовка аудио`, `Декодирование нот · Chunk 6`, `Формирование MIDI`, `Размещение на дорожке` |
| Ошибки | Человеческое сообщение; детали в diagnostics. Crash/timeout/cancel не интерпретировать как успешную конвертацию |
| Отмена | Worker cancel + cleanup, без частично созданных дорожек/клипов |

Отображать реальный объём обработанного аудио в секундах и/или `30 из 50 секунд` рядом с chunks, когда worker может сообщить это достоверно. Закрытие окна во время обработки не должно оставлять фоновую неконтролируемую задачу: отмена и понятное подтверждение в логике MR Studio.

## 4. Сценарий B: полный микс → несколько MIDI-дорожек

![Диалог полного микса](mockups/04_mix_convert_dialog.png)

1. ПКМ на выделенном audio clip / допустимом выбранном диапазоне → `Convert to MIDI`.
2. Показывать **только источник + модель** (`MuScriptor Medium`) и `Отмена` / `Распознать партии`.
3. После запуска использовать **то же** окно прогресса, что в сценарии A. Модель распознаёт **все** instrument groups, без заранее установленного ограничения.
4. По завершении открыть компактное окно извлечённых партий с названиями **из фактического результата**, не фиктивными примерными треками.
5. Галочками выбрать партии; предоставить `Выбрать все` и `Снять все`; кнопка `Создать N MIDI-дорожек` пересчитывает N и неактивна при 0.
6. Одним действием создать по выбранным партиям обычные инструментальные/MIDI дорожки + MIDI-клипы. **Без дополнительного wizard назначения VSTi, GM channel, velocity, plugin.** Пользователь настроит инструменты после создания.
7. Вся вставка — **одна атомарная Undo-транзакция**. Если ошибка/пустой результат, не оставлять пустые дорожки и partial state.

![Галочки у извлечённых партий](mockups/05_select_extracted_parts.png)

Имена `Electric Bass`, `Piano`, `Drums`, `Acoustic Guitar`, `Strings` и число `3 из 5` на макете — только **иллюстрация**. Список должен совпадать с реальным выводом модели. Драм-партия — MIDI-партия, физические MIDI-каналы стандартно ограничены 16 на порт.

## 5. Preferences → Audio-to-MIDI

![Настройки Audio-to-MIDI](mockups/06_preferences.png)

| Раздел | Параметр | Поведение |
|---|---|---|
| Производительность | `CPU Threads` | `Auto` или доступное ограниченное число потоков; сохраняется между запусками |
| Производительность | `Compute Device` | CPU; CUDA/другие устройства показывать только если реально доступны в установленном runtime |
| MIDI | `Quantization` | `Off` по умолчанию, исходный timing не менять скрыто |
| MIDI | `Grid / Strength` | Активны только при Quantization On; поддержать сетку/триоли и силу квантизации в модели или общем MIDI processing |
| MIDI | `Default velocity` | Резервное значение (макет: `100`). **MuScriptor Medium не предсказывает velocity**; у будущих моделей с native velocity не затирать распознанное значение |
| Модели | `Model Manager` | Отдельный доступ к установке и проверке реально поддерживаемых моделей; пока Medium |

**Snapshot:** перед запуском зафиксировать все настройки job; изменение Preferences во время работы влияет только на следующий job.

## 6. Ошибки, жизненный цикл и контракт backend

| Ситуация | Ожидаемое поведение |
|---|---|
| Обычный клик по клипу | Не запускает drag/конвертацию; drag только при преодолении принятого порога перемещения |
| Drop на Audio/Bus/Folder/неподдерживаемую дорожку | Не конвертировать; соответствующий курсор/подсказка, никаких клипов |
| Drop рядом с границей таймлайна | Применить snap и реальную позицию target drop без случайного сброса `source_offset` |
| Target track удалён/поменялся во время inference | Проверить актуальные идентификаторы/revisions перед commit, не воскрешать и не перенаправлять клип |
| Пользователь отменил / worker упал | Отмена процесса, очистка временных файлов и ресурсов; zero mutation проекта |
| В результате нет нот/партий | Понятное уведомление, не создавать пустые MIDI-треки |
| Модель отсутствует | Честный статус в UI/Model Manager; без скрытой загрузки |

**Request minimum:** `jobId`, `sourceClipId`, `sourceRevision`, фактический `selectedAudioRange` (sample boundaries и sample rate), `targetTrackId`/drop position (для A), source timeline position (для B), `modelId=MuScriptor Medium`, `instrumentGroup` (ровно один в A, без ограничения в B), snapshot настройки CPU/device/quantize/velocity.

**Event minimum:** `queued` → `loading_model` → `preparing_audio` → `decoding_chunk(index,total,processedSeconds)` → `postprocessing_midi` → `placing_result` → `completed(resultManifest)`; терминальные `cancelled` / `failed(code,message)`. Отчёт worker — источник данных UI; время — локальный monotonic elapsed. Размещение только после полной валидации результата.

Не создавать второй MIDI-процессор и собственный Piano Roll. Переиспользовать текущие Commands/Project Model/MIDI Editor, сохранить Undo/Redo/Save/Open/Save As, надёжный seconds→ticks при tempo-map changes, clip trim/offset и source provenance. **Никаких Python/ML/disk I/O в audio callback**. Не затрагивать MR Separation, MR Live и параллельно разрабатываемые модели.

## 7. Приёмка (чек-лист)

- [ ] Выделить часть WAV без разрезания → drop на VSTi Instrument Track → два поля → общий прогресс → **один** MIDI-клип в правильной позиции, WAV неизменно.
- [ ] Готовый Bass Stem → инструмент `Electric Bass` → MIDI на существующей дорожке без окна партий.
- [ ] Click без drag и drop на Audio/Bus/Folder ничего не создают.
- [ ] Полный микс через ПКМ → **одно** поле модели → прогресс → реальные партии → Select All/None → **N** новых MIDI-дорожек.
- [ ] При пустом списке / 0 галочек кнопка создания отключена, пустые дорожки не создаются.
- [ ] `Chunks n/N`, elapsed и текущая операция обновляются по worker; процент честно учитывает load/prepare/postprocess или заменён indeterminate.
- [ ] Cancel/worker crash/timeout на каждой стадии не оставляют клипов/пустых дорожек/зомби-worker/temp-файлов.
- [ ] Preferences сохраняются и применяются только к следующему запуску; CPU Threads не появляется в двух стартовых диалогах.
- [ ] В UI доступна только MuScriptor Medium; не появляются C++ HOT-Step A/B, Small/Large.
- [ ] Проверены nonzero trim, source offset, tempo-map changes, snap/drop position, Undo/Redo/Save/Open/Save As.
- [ ] Адресные Studio-only Windows/ARA2 ON проверки по AGENTS.md; пользовательская слуховая/музыкальная проверка отдельно.

## 8. Указания рабочему чату

1. Сверить **актуальные** `main` и ветку разработки, `AGENTS.md`, существующие Audio-to-MIDI Issues и релевантный код. ТЗ не свидетельствует о реализации.
2. Делить внедрение на небольшие этапы **в рамках существующей архитектуры**; обновлять Issues только по отдельной команде пользователя.
3. Очерёдность: поддержка target drop/одной категории и общий компонент прогресса → full-mix flow/список партий → Preferences и регрессии.
4. После этапов предоставить реальные screenshots и визуально сравнить с `mockups/01..07` (поля, порядок, отступы, состояния). Значимые расхождения согласовывать, а не самостоятельно заменять дизайн.
5. Не делать merge в `main` и не закрывать Issues без пользовательской приёмки; не начинать другие backend/модели, изменять C++ или MR Live.
6. **Вне scope:** новые ML-модели, MusicXML/PDF, предсказание velocity для Medium, C++ портирование, лицензирование, новый мастер назначения VSTi, полный редизайн таймлайна.
