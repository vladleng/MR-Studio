# Track folders and Folder Bus

Arrange supports Ctrl-click and Shift-click selection on track headers. Right-click a track header and use **Group selected tracks in folder...** or **Move selected tracks into folder**. Clicking the folder header (or Return/Space with that header focused) expands/collapses its lanes. The header's context menu supports rename, moving selected tracks into the folder, and dissolving the folder. Collapsed tracks continue to play; their clips are excluded from visible hit/drop targets. Arrange and Mixer share the same collapsed state and update immediately without another click or window resize. Collapsed member clips stay visible in Arrange as compressed bands inside the folder lane; those bands are presentation only and never become hit or drop targets. A folder without a Bus keeps the slim Arrange header. A folder with a linked Bus is presented by that Bus channel itself: the row sits at the folder position with the folder toggle and context menu, and the Bus no longer appears as a separate lane at the end of the track list. A Bus row is a channel, not a clip lane, so dropping or moving clips onto it is refused.

The channel inspector is the durable place for the remaining Bus settings. A small **i** button in the bottom-left corner shows or hides a dock to the left of the Arrange channels: name, colour, gain, pan, mute/solo, output, inserts (add, bypass, drag, editor, context menu) and sends (level, bypass, destination). CPU and latency readouts stay right of that button. A selected folder without a Bus shows the folder name and **Create and link Bus** instead of channel controls. Folders, strips and the inspector read the same project data and call the same commands; the inspector owns no project state and its visibility/width live in view settings, so project schema and Undo are unchanged. Mixer keeps presenting each folder as a simplified channel (name, folder icon, expand/collapse, context menu); a linked Bus is that same channel, and its existing gain, pan, mute, solo and meters remain available.

A folder is presentation/membership state, not another audio channel. **Create and link Bus** creates one ordinary Bus and links it in the same undo transaction. **Link existing Bus** assigns member audio/instrument/main Bus outputs to that Bus, clearing their explicit hardware outputs. MIDI-only tracks retain their MIDI routing. Existing sends and insert chains are retained; standard graph validation rejects feedback atomically. A Bus can be linked to one folder. Nested folders retain their own linked Bus; nested Bus channels placed in their parent folder feed that parent's linked Bus.

Moving a track into a linked folder applies that folder's Bus output. Moving it out, detaching a Bus, or dissolving a folder preserves current audio routing and does not delete channels or clips. These actions explicitly say **keep routing** where relevant. Undo restores the original membership/routing together. Removing a linked Bus clears its folder link and uses the existing Bus removal routing behavior.

Grouping, rename and collapse are available during playback. Changes to routing/channel topology use the existing stopped/paused graph lifecycle. All folder membership, names, collapsed state and Bus links persist in project schema 30; schemas 1–29 load with default expanded folders and no Bus links. Older versions of MR Studio cannot open schema 30 projects.

Mixer scalar updates have a serial independent of the transport/DSP invalidation generation. Already prepared PCM remains audible while new targets ramp over 5 ms in their processing owner. Ahead channel response is bounded by the configured Process Buffer; live channels respond in the device callback. Transport/processor generation changes still invalidate speculative PCM. The mixed renderer transfers complete target snapshots through its preallocated context mailbox, without sharing mutable mixer state between processing owners.
