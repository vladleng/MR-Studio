# Patches — логика MR Live (#289)

## Структура патча

1. **Patch** — общая цепочка всех insert-плагинов канала и их сохранённое состояние. Содержит Sub-patches (Main, Rhythm, Solo и любые другие пользовательские варианты).
2. **Patch 2** — другая цепочка со своими Sub-patches (Rhythm, Solo, Wah и т. д.).

Названия Patch, Main, Rhythm, Solo, Polytone, RC J120 и другие — примеры, их создавать автоматически **не нужно**. Единственный автоматически создаваемый Sub-patch — `default`.

## Принятые меню (не изменять в #374 Stop-fix)

**ПКМ по пустой области дорожки Timeline:** `+ Patch`, `Default`, далее существующие Patch по именам.

**ПКМ по верхней области Patch:** `+ Patch`, `Rename`, `Delete`, `Update`, `Replace` → только существующие Patch.

**ПКМ по Sub-patch:** `+ Sub-patch`, `Rename`, `Delete`, `Update`.

**ЛКМ по Sub-patch:** список вариантов **этого же Patch** для переназначения выбранного сегмента. Заголовок канала не содержит Patch-меню.

## Создание / обновление

1. `+ Patch` захватывает **актуальную** insert-цепочку из активного Core / Live Input, включая реальные VST3 component/controller state. Нельзя захватывать устаревшее поле `channel.liveInput.inserts` вместо действительного звука. Отдельно сохраняются доступные нормализованные параметры для сравнения.
2. Сразу создаётся настоящий Sub-patch `default` на **всю длину** Patch. Он может быть переименован и обновлён как любой другой. Скрытый второй Base или дополнительная копия DSP-цепочки не создаётся.
3. `+ Sub-patch` снимает текущее состояние той же цепочки. Вариант может храниться как sparse parameter overrides или VST3 Snapshot; это технический формат, не новое меню для пользователя.
4. Звёздочка у названия Sub-patch отображает достоверно обнаруженное отличие текущего звука от сохранённого и исчезает после `Update`.
5. При `Patch → Update` изменение состава плагинов обновляет **общую цепочку**: новые плагины наследуются вариантами, удалённые ссылки/параметры исключаются, существующие совместимые состояния сохраняются. `Sub-patch → Update` изменяет только выбранную вариацию.
6. Старые пользовательские Patch мигрировать/восстанавливать не нужно.

## Единственный источник назначения звука

- Назначение звука на позиции Item определяется **Timeline `tracks[].spans`** — библиотечным Patch ID и вложенным Sub-patch ID. Устаревшие `tracks[].patchId/subPatchId` не должны отдельно переопределять Timeline.
- После Scissors каждый блок имеет самостоятельный ID и ссылку на исходный библиотечный Patch/Sub-patch. Это не копирование состояния плагина.
- Интервалы `[start, end)`; на стыке активен **правый** блок. Sub-patch позиционируется относительно начала родительского Patch. Внутренних пробелов у Sub-patch быть не должно: все сегменты подряд покрывают длину родительского Patch. Если Patch на позиции нет, не загружать произвольный старый Item default.
- `Default` в меню пустого трека — отсутствие отдельного назначенного Patch, не новый скрытый Patch. Не путать с первым Sub-patch `default`.

## Переключение в Stop — текущий этап #374

1. При одиночном ЛКМ по телу Patch (не drag/Shift/Scissors) загружается звук Patch/Sub-patch под указателем в активный Live Input. Существующие жесты редактирования не изменяются.
2. При выборе другого Sub-patch из списка ЛКМ переназначается **только этот сегмент** и в Stop загружается его сохранённое состояние (Parameters или Snapshot).
3. Добавление/Replace существующего Patch на текущем Item в Stop загружает соответствующий звук, не меняя других сегментов или микс канала.
4. При переходе к другому Item в Stop начальный звук определяется Patch/Sub-patch на позиции **0** Timeline. Не использовать прежнее поле Item default.
5. Возврат на `default` восстанавливает полный сохранённый звук Patch, без оставшихся параметров предыдущей вариации. Фейдер, панорама, входы/выходы не переписываются.
6. После Save/Reopen, Undo/Redo и повторного выбора результат должен совпадать; отсутствие плагина или несовместимое состояние показывать явно.

## Переключение в Play — отдельная Issue #375

- Автоматическая смена Patch/Sub-patch **на музыкальных границах блоков** по позиции Transport.
- Preload/warm и VST3 Snapshot-подготовка вне audio callback, RT-safe bounded очередь параметров и публикация подготовленного графа. Запрещено выполнять opaque `setState` прямо в callback.
- При небезопасной подготовке удержать текущий звук и сообщить причину. Проверить PDC/latency, tails, lifetime и xrun. Это не требует seamless между Item (#301).
- **Блоки Timeline сами по себе не означают, что автоматическое переключение в Play уже работает.**

## Уточнение после теста 0.9.3-Upd6 — непрерывная Sub-patch rail

**Пользовательская приёмка:** обычные Patch переключаются; Sub-patch пока **не переключают звук**. Это незавершённый функциональный дефект #374, не переносить в #375. Производного `Base` в UI и новых данных **не должно быть**. Вместо него — настоящий библиотечный Sub-patch `default`, как согласовано ранее.

- Область нижних сегментов непрерывно покрывает **всю длину родительского Patch** от первого до последнего края. Если Patch занимает весь Item, Sub-patch rail занимает весь Item; если Patch меньше Item, границы привязаны к Patch. В каждом такте — ровно один назначенный Sub-patch.
- Крайний слева сегмент начинается ровно в 0 относительно Patch; крайний справа заканчивается точно в `Patch.length`. Тело сегмента не двигается независимо; для изменения длительности перемещается **только общая граница двух смежных сегментов**. Ни Resize, ни Delete, ни Scissors, ни изменение размера Patch не создают пустых промежутков.
- **ЛКМ по сегменту**: выбрать существующий вариант текущего Patch из быстрого меню и применить его сохранённый VST3 звук при **Stop**. Если сегмент уже выбран, повторная загрузка также должна восстановить звук после редактирования плагина. В Play горячее переключение остаётся #375.
- **ПКМ по Sub-patch**: `+ Sub-patch` открывает варианты вставки. Можно захватить текущий звук как новую библиотечную вариацию либо выбрать **уже существующую** вариацию. Вставка начинается в точке клика, привязанной к сетке 1/4 такта; по умолчанию новый сегмент длится 1 такт, а предыдущий звук сохраняется слева и справа; не оставлять Base. На слишком коротком участке — явный отказ, а не скрытый перенос вставки в другое место.
- **Scissors:** разрезает текущий Sub-patch на два соседних сегмента с **одним и тем же** библиотечным ID. Затем для каждой половины можно ЛКМ выбрать разные существующие варианты. Нарезка сама по себе не создаёт новых библиотечных состояний.
- **Удаление сегмента:** если сегментов несколько, соседний (предпочтительно слева, у левого края — справа) расширяется на удалённый интервал. Единственный сегмент нельзя удалить независимо от Patch; можно заменить его вариант либо удалить весь Patch. Удаление библиотечного Sub-patch переадресует связанные сегменты на оставшийся вариант, не образуя пустот.
- Источник актуальных значений VST3 при Capture/dirty — реальные нормализованные текущие параметры после `performEdit`, а не первоначальное `ParameterInfo.initial`; дополнительно проверять применение opaque Snapshot, восстановление `default`, Save/Reopen, Undo/Redo и физический vendor VST3. Данные не читать в audio callback.

**Критерий #374:** при Stop переключение `default → Solo → default` слышимо, у Sub-patch нет ни одного участка `Base` или тишины из-за пустого слота, а действия с границами сохраняют полное покрытие. #375 — только музыкально синхронизированное переключение во время Play с RT safety.
