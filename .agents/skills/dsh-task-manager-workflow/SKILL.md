# DSH Task Manager: короткий рабочий цикл

Этот скилл управляет **записью задачи**, а не кодом и не способом тестирования. Соблюдай текущий запрос и проектный AGENTS.md.

1. Для вопроса или аудита — только чтение. Не меняй запись задачи и код без поручения.
2. Если ID задачи известен, вызови `tasks_get` напрямую. `tasks_list` используй только для поиска неизвестного ID. Родительскую задачу читай, только если её границы нужны для текущей работы. Не сканируй весь журнал.
3. Из назначенной записи возьми цель, scope и критерии приёмки. Не добавляй требований и не создавай дублирующих задач.
4. При поручении создать задачу или подзадачу используй `tasks_create` в согласованной структуре. Не создавай дубликаты и не перестраивай существующую иерархию без разрешения.
5. При начале выполнения допускается статус `wip`. Обновляй запись **после значимого этапа**, а не после каждого вызова инструмента. Пиши кратко: результат, проверка, следующая операция. Не переносить большие логи в комментарии.
6. Для завершённой реализации запиши проверенные факты и ограничения, поставь `wait` — ожидание пользовательской приёмки. `blocked` — только при настоящей внешней блокировке, а не при обычном падении теста.
7. Статус `done` ставь только после явной приёмки пользователя. Закрытие подзадачи не закрывает родительскую; технический PASS не равен приёмке.
8. Не делай merge, push, удаление, архивирование задач или создание новых этапов без соответствующих полномочий. Статусы задачи не заменяют состояние кода и Git.
9. После сбоя или нового чата: прочитай назначенную задачу и последний существенный комментарий, затем сверь локальный Git и фактические файлы. Не повторяй подтверждённую работу.

Используй API плагина (`tasks_get`, `tasks_update`, `tasks_comment_add` и инструменты чек-поинтов) только по необходимости. Проверяй результаты вызовов. Не редактируй хранилище Task Manager напрямую.
