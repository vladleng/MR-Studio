# Адресный поиск локальных команд и целей

Используй **только если** нужно установить реальный способ запуска из текущего checkout. Не выводи команды из исторического CI.

1. Проверь интерфейс `tools/Build-Local.ps1`, затем при необходимости `tools/Enter-DevEnvironment.ps1`, `CMakePresets.json` / `CMakeUserPresets.json`, `CMakeLists.txt` и фактические targets существующего дерева сборки. Не считай примеры параметров гарантированным текущим API скрипта.
2. Выбери узкий поддерживаемый сценарий: `Core` / `Studio` / `Live` / `Both`, нужный target и адресные tests. Если скрипт не поддерживает точный scope, проверяй presets и фактическую CMake-конфигурацию перед ручным запуском. Не придумывай параметры и имена targets.
3. Проверяй SDK и toolchain по актуальным локальным `tools/ci/sdk-lock.json` и реальному окружению. Не скачивай/устанавливай зависимости автоматически ради проверки документации. Не удаляй и не перенастраивай существующий build tree без необходимости.
4. Если базового правила недостаточно или есть спорный случай уровня проверки, открой **только соответствующий раздел** `docs/LOCAL_BUILD_POLICY.md`. Глобальные ограничения операций Git, DSH Task Manager, пользовательской приёмки и Actions уже определены в корневом `AGENTS.md`.
5. Для воспроизводимости фиксируй реальную команду, уровень/targets, OS/toolchain, ветку/HEAD/dirty state, PASS/FAIL/NOT TESTED и нерешённые аппаратные проверки. Логи не добавляй в Git; веди записи в назначенной DSH-задаче, если это входит в поручение.
