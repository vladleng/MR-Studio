# MR Studio — Native Plugin SVG Kit 01

Единый визуальный язык для нативных плагинов **MR Studio**. Оригинальная система, вдохновлённая предоставленным скриншотом Synth Anthology 4: графитовые панели, холодные светло-голубые контуры, минимум деталей, линейные иллюстрации аппаратуры, небольшие активные индикаторы. **Не копия интерфейса или изображений исходного продукта.**

## Содержимое

- `svg/controls/` — 23 примера регуляторов, переключателей, индикации и графиков.
- `svg/rig/` — 12 линейных изображений гитарного оборудования и педалей для **MR Rig**.
- `svg/reverb/` — 11 изображений аппаратов, IR и акустических пространств для **MR Reverb**.
- `svg/icons/` — 19 пиктограмм с viewBox 24×24.
- `tokens/` — палитра и базовые CSS/JSON design tokens.
- `previews/` — HTML-каталог, PNG-контактный лист и два полноразмерных концепта интерфейсов (SVG + PNG).

**Базовый набор: 65 отдельных SVG элементов + 2 концепта панелей.**

## Fader, Control, Track & Utility Pack — 2026-10-16

По двум предоставленным концептам добавлены **155 оригинальных SVG**, без изменения прежних SVG. Общий manifest теперь содержит **220 элементов**; ещё **16 ссылок** в каталоге расширения используют существующие пиктограммы и транспорт (это ссылки, не дополнительные новые SVG).

- `svg/controls/concept_pack/` — Micro / Slide / Precision: normal, hover, active, focus, automation, disabled; отдельные track/fill/thumb; LED meters; шкалы; mute/solo/record; pan; поля значений; рамки toolbar/transport; цветные теги дорожек; декоративные waveform; dividers/spacers.

Отрисованы заново по пользовательским концептам; raster, логотипы других продуктов, шрифты и внешние зависимости в SVG не включены. Исходные PNG-концепты остаются в пользовательской папке `images/`, не включаются в распространяемый набор. Геометрия плоская, без растра, свечения и фильтров. Индивидуальные SVG имеют прозрачный внешний холст; обзорные листы имеют тёмный фон и обычные подписи для просмотра.

### Подключение в будущем

Библиотека используется выборочно в рабочем GUI: M/S/arm, поля значений, типы дорожек и action icons; Micro/Slide/pan/LED meters рисуются динамически по текущим host values. [Контракт runtime-внедрения](../../../docs/MR_SVG_RUNTIME.md). Остальные варианты остаются материалом для последующих этапов. Сами SVG не реализуют ввод, клавиатуру, доступность, автоматизацию, измерение уровней или DSP. Статические meters и waveforms явно помечены как образцы и в рабочий UI вместо показаний движка не подключаются.

Фейдеры: host рисует/обрезает fill по нормализованному значению и перемещает thumb; диапазон оси указан в tokens, origin статического примера — в catalog. Автоматизация дополнительно обозначена ромбом. Положение образцов = 0.55, округлённое до пикселя, без приписывания значения dB. Шкалы содержат только риски: реальные подписи и нелинейная шкала берутся из метаданных параметра. Для загрузки отдельных слоёв никаких изменений SVG не требуется.

Числа, единицы, названия и номера дорожек рисует host поверх `text_slot`/`text_inset`; glyph размещается в `icon_slot` рамки. Поэтому поля значений и теги в каталоге пустые — это переиспользуемая основа, а не зашитые «−6.0» и «1». Для тегов указан контрастный `text_color`. Варианты On и automation имеют дополнительные геометрические признаки; имя/состояние остаются обязательными для accessibility. Размер картинки не равен hit area: целевой размер ввода задаёт host, минимум 32 логических px для компактного desktop-контрола, больше при необходимости и в Live.

### Пересборка и проверка расширения

Из корня проекта, Python 3 и Node с установленным `sharp` (доступ через обычный resolution или `NODE_PATH`):

```powershell
python assets/ui/mr-uds/build_concept_pack.py
python assets/ui/mr-uds/validate_concept_pack.py
node assets/ui/mr-uds/render_concept_pack.cjs
```

Новый генератор записывает только собственные SVG/каталог/tokens/HTML и свои entries в root manifest. Валидатор проверяет XML, размеры, отсутствие небезопасных/внешних элементов, согласованность manifest и ссылки, затем собирает два обзорных SVG. Рендерер проверяет все 155 SVG на 100/125/150/200% (620 образцов), создаёт PNG и локальный отчёт `build/validation/svg-concept-pack/render_report.json`. Это программная растеризация, не проверка физического DPI или поведения native JUCE controls. Нативный экран с этим набором ещё требует отдельной интеграции и приёмки.

**Старый `build_kit.py` — legacy full rebuild:** перезаписывает базовый manifest, README и прежние previews, создаёт ZIP. Для работы с расширением его не запускать; использовать три команды выше. Старые previews и SVG сохранены.

## Принципы интеграции

1. Иллюстрации оборудования и иконки — статическая векторная графика с прозрачным фоном. SVG не содержат растровых вложений, фильтров, внешних шрифтов и внешних зависимостей.
2. Интерактивные элементы (`knob`, `slider`, `meter`, `toggle`) — **визуальные образцы состояний**, не заменяют полноценные контролы и не реализуют ввод. Для реального GUI лучше рисовать контур программно, а SVG использовать как стиль и референс либо менять геометрию по параметрам.
3. ViewBox для controls = 160×140; rig/reverb = 320×200; icons = 24×24. Масштабирование сохраняет линии, но для миниатюр необходимы отдельные LOD-версии или предельная плотность деталей.
4. Не встраивать названия параметров из примера как статический текст в интерактивные контролы — реальные подписи должны приходить из UI и состояния плагина.
5. Цвета заданы прямо в SVG ради предсказуемого рендера (в том числе в Qt SVG). При адаптации темы можно заменить шестнадцатеричные значения на этапе загрузки или конвертировать SVG в пути и назначить цвета средствами хоста.
6. **UI/аудиопотоки разделять**: отображение SVG и управление состоянием работают на UI-потоке, передача параметров в DSP — штатным realtime-safe механизмом. Не вводить рендеринг SVG в audio callback.
7. Активные элементы: акцент `#91BBEE` для выбранного, `#7AB69E` для включено, `#E68F88` — сигнализирующий индикатор. Не превращать весь интерфейс в ярко-синее свечение.
8. Для компактности ориентироваться на шаг 4 px, шапку ~48 px, радиус больших карточек 12–15 px; основной контур 1–1.6 px, подписи 10–12 px при проектном масштабе.
9. Для MR Rig: усилитель и кабинет — крупная контурная схема (не фотореализм), рядом реальные параметры; цепочка эффектов — компактными карточками.
10. Для MR Reverb: визуализация комнаты или устройства / центральная форма IR / простое управление decay, predelay, diffusion, mix. Отдельные send-режимы должны подключаться к маршрутизации DAW, не кодироваться в графике.
